## 🏛️ الأعمدة الخمسة للاختبارات

### 1. العمود الأول: منطق الأعمال وانتقالات الحالات
* **الملف المنظم:** `tests/e2e/run-all.ts`
* **أمر التشغيل:** `npm run test:e2e`
* **النتيجة:** 245/245 اجتياز تام بنسبة 100% (زمن التشغيل: ~2.5 ثانية).
* **التغطية:**
  - **Tier 1 (Feature Coverage — 98 اختباراً):** تغطية الميزات من F1 إلى F17 (إنشاء الطلبات، شجرة الحالات، العملاء، دليل الوجبات، الورديات، الإغلاق اليومي، سجل التدقيق، إدارة المستخدمين، المصروفات).
  - **Tier 2 (Boundary & Corner Cases — 65 اختباراً):** التحقق من حالات الحدود القصوى، أطوال النصوص، انعدام الأخطاء عند تمرير قيم فارغة، الحصانة من القسمة على صفر، والحدود القصوى للخصومات.
  - **Tier 3 (Cross-Feature Combinations — 72 اختباراً):** مصفوفة التفاعل المتبادل بين العملات، طرق الدفع، حسابات التوصيل، تناسق الترجمة الثنائية، وتوليد ملفات الإكسل الأصلية والـ PDF.
  - **Tier 4 (Real-World Scenarios — 10 سيناريوهات):** محاكاة تفصيلية واقعية لوردية الكاشير، شاشة المطبخ، ومراقب الطلبات المتأخرة.

### 2. العمود الثاني: المتصفح الحقيقي وتجربة المستخدم (Playwright)
* **الأداة:** `@playwright/test` مع متصفح Chromium وحسابات نظام حقيقية على قاعدة بيانات Supabase.
* **أوامر التشغيل:** `npm run test:pw` (عربي RTL)، `npm run test:pw:en` (إنجليزي LTR)، `npm run test:pw:tablet` (تابلت).
* **النتيجة:** 47/47 اجتياز تام بنسبة 100%.
* **السويتات المنفذة:**
  1. `auth.spec.ts`: تسجيل الدخول، الحماية من الدخول غير المصرح، وإعادة التوجيه للوحة المناسبة.
  2. `order-entry.spec.ts`: إدخال الطلب بسرعة فائقة، البحث عن العميل برقم الهاتف، وتطبيق الخصم واختيار الأصناف.
  3. `orders-kanban.spec.ts`: شاشة المطبخ (Kanban)، سحب وانتقال الطلبات، والعدادات التنازلية الحية.
  4. `closing.spec.ts`: معاينة الوردية الحية، تدقيق إجمالي الكاش، وتأكيد الإغلاق اليومي.
  5. `audit.spec.ts`: سجل التدقيق، تصفية العمليات، ونافذة الفحص البصري للمالك.
  6. `customers.spec.ts`: دليل العملاء، تقسيم RFM، وتنزيل شيت إكسل `.xlsx` الأصلي مع مؤشر التحميل.
  7. `reports.spec.ts`: لوحة التحليلات، الرسوم البيانية، طباعة الـ PDF، واستخراج شيت العمليات الشامل.
  8. `users.spec.ts`: إدارة المستخدمين، تعديل الأدوار، وحظر الكاشير من دخول الصفحة.
  9. `i18n.spec.ts`: فحص اتجاه النصوص (RTL/LTR)، تبديل اللغات، وانعدام أخطاء `MISSING_MESSAGE`.

### 3. العمود الثالث: أمان الواجهات البرمجية والصلاحيات والحصانة
* **الملفات:** `tests/security/rbac-penetration.test.ts` و `tests/security/immutability.test.ts`
* **أمر التشغيل:** `npm run test:security`
* **النتيجة:** 70/70 اجتياز تام بنسبة 100%.
* **المحاور المغطاة:**
  - **مصفوفة اختراق الصلاحيات (RBAC Penetration Matrix — 64 اختباراً):**
    - اختبار 16 مسار API حساس ضد الطلبات غير المصرح لها برفض حتمي `HTTP 401 Unauthorized`.
    - اختبار كافة الأدوار غير المخولة (مثل محاولة الكاشير اعتماد خصم أو الدخول للتقارير أو المستخدمين) برفض حتمي `HTTP 403 Forbidden`.
    - التأكد من نجاح واستجابة المسارات للأدوار المصرح لها فقط (`OWNER`, `MANAGER`, `CASHIER`).
  - **الحصانة المطلقة وعدم الحذف (No-Hard-Delete Invariant — 6 اختبارات):**
    - التأكد برمجياً من عدم تصدير أي دوال حذف نهائي `DELETE` في خدمات ومسارات الطلبات.
    - إلزامية سبب الإلغاء الصريح (`CancelReason`) ومنع الإلغاء بدونه.
    - حظر التعديل أو الحذف على سجل التدقيق ودليل العملاء بردع فوري `HTTP 405 Method Not Allowed`.
    - فرض الحذف المنطقي (`isActive=false`) لجداول المنيو وقوائم المستخدمين.

### 4. العمود الرابع: الصفرية المالية والتطابق المحاسبي العشوائي
* **الملف:** `tests/stress/financial-fuzzer.test.ts`
* **النتيجة:** 3/3 سويتات بنجاح 100% (زمن التشغيل: ~107ms).
* **المحاور المغطاة:**
  1. **فحص 10,000 طلب عشوائي:**
     - التحقق التام من معادلة الإيراد الإجمالي: `totalCash + totalVisa + totalOnline === totalRevenue`.
     - التصفير التام لرسوم توصيل أسطول التطبيقات (`driverType === APP ➔ netDeliveryFee = 0`).
     - انعدام القيم السالبة في المجاميع حتى لو تجاوز الخصم قيمة الطلب (`total >= 0`).
  2. **فحص 100,000 رقم عشوائي بفاصلة عائمة:**
     - ثبات واستقرار دالة التقريب المالي `roundCurrency` وانعدام أي تسريب أو انحراف (> 0.01).
  3. **مطابقة 500 وردية عشوائية:**
     - معادلة الخزينة الصارمة: `netCash === totalCash - totalExpenses`.
     - استبعاد الطلبات الملغاة كلياً من الإيرادات والرسوم.

### 5. العمود الخامس: ضغط الذروة، التزامن، التابلت، ومعايير الأداء
* **الملفات:** `tests/stress/concurrency.test.ts`، `tests/playwright/responsive.spec.ts`، `tests/stress/performance.test.ts`
* **أوامر التشغيل:** `npm run test:stress` و `npm run test:pw:tablet`
* **النتيجة:** 11/11 اجتياز تام بنسبة 100%.
* **المحاور المغطاة:**
  1. **محاكاة ساعة الذروة (Rush Hour Concurrency):** إطلاق 10 طلبات متزامنة في نفس اللحظة والتحقق من حصول كل طلب على رقم تسلسلي فريد وغير مكرر نهائياً (`ORD-YYYYMMDD-XXXX`).
  2. **استجابة شاشات التابلت (Tablet Viewport — iPad Pro 11):** فحص انعدام التمدد الأفقي للشاشات والتأكد من ملاءمة عناصر التحكم واللمس بحجم `>= 44px`.
  3. **مطابقة معايير الأداء غير الوظيفية (NFR Compliance):**
     - زمن استجابة لوحة التحكم: **~411ms** (معيار NFR: < 2000ms).
     - تجميع تقارير 30 يوماً: **~438ms** (معيار NFR: < 3000ms).
     - استعلام سجلات الإغلاق: **~219ms** (معيار NFR: < 3000ms).
     - استعلام دليل العملاء مع تقسيم RFM: **~162ms** (معيار NFR: < 1500ms).
     - معالجة 10,000 عملية مالية في الذاكرة: **10.3ms فقط** (معيار NFR: < 200ms).

## 🛡️ الثوابت الصارمة المحققة (Verified Architectural Invariants)

1. **انعدام الحذف الصلب (No Hard Delete):** استحالة حذف أي طلب أو سجل عميل أو سجل تدقيق، والاعتماد الحصري على الحذف المنطقي والإلغاء بسبب إجباري.
2. **صفرية تسريب الكاش (Zero Cash Drift):** مطابقة تامة للمعادلات المحاسبية الحتمية في كل وردية وفي كل عملية طلب.
3. **نموذج الدارك كيتشن 100% دليفري وصفرية النقاط:** اقتصار العمليات على التوصيل فقط، وقياس ولاء العملاء بالسلوك الفعلي (RFM) بدون نقاط وهمية.
4. **تصدير الإكسل الأصلي `.xlsx` (Native Excel):** إنتاج ملفات حقيقية منسقة بـ RTL وأرقام قابلة للحساب وكروت KPIs، مع مؤشر تحميل ودوران.
5. **تناظر الترجمة الصارم (i18n Symmetry):** تطابق بنسبة 100% بين ملفي `ar.json` و `en.json` وانعدام تام لأخطاء `MISSING_MESSAGE`.
